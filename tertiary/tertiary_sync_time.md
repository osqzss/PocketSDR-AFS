# AFS-Q Tertiary Code 同期時間について

AFS-Q の tertiary code は 1 周期が 12 秒（1500 チップ × 8 ms）ですが、
PocketSDR-AFS では信号捕捉から約 3.5 秒、受信開始から約 4 秒で tertiary code
同期が確立します。本書はその理由をまとめたものです。

## 1. 1 周期を待たずに同期できる理由

同期で求めるのは、受信したチップ列が 1500 チップの符号のどの位置にあたるか
（位相）だけです。符号の全周期を受信する必要はありません。

- `search_ter_code()`（`src/sdr_ch.c`）は、受信した tertiary シンボル
  （最低 250 個 = 2 秒分）を 1500 通りすべての位相候補と相関させます。
- tertiary code は Weil 系列で、ほぼランダムな系列です。250 チップの部分列で
  相関をとると、次のようになります。
  - 正しい位相：全チップが一致し、正規化相関は約 1.0 です。
  - 誤った位相：一致・不一致がランダムになり、相関は ±√250 ≈ ±16 程度
    （正規化で約 0.06）です。1500 候補の最大値でも 3.5σ 程度
    （正規化で約 0.25）にとどまります。
- 同期判定の閾値 `THRES_TSYNC = 0.8` との間には十分な差があるため、2 秒分の
  シンボルで位相を一意に決められます。

GPS L1 C/A の航法データで、プリアンブルを検出すれば 30 秒のフレーム全体を
待たずにフレーム同期できるのと同じ考え方です。

## 2. 同期時刻の内訳

`afssim_iq2.bin`（LANS-AFS-SIM で生成）を `pocket_trk` で処理したときの
`log.txt` から、PRN 2 の例を示します。

| 段階                                                         | 時刻 [s]  |
|--------------------------------------------------------------|-----------|
| 信号捕捉（SIGNAL FOUND）                                     | 0.766     |
| + `T_NPULLIN` = 1.5 s（追尾が安定するまで待ち、その後 secondary code 同期） | 2.27      |
| + `N_TSYNC` = 250 シンボル × 8 ms = 2.0 s                    | **4.27**  |

ログの `TERTIARY CODE SYNC` は 4.270 s で、この計算と一致します。
他の PRN も同様に、捕捉時刻 + 3.5 s で同期しています。

```
$LOG,0.766,AFSP,2,SIGNAL FOUND (42.1,-1499.7,0.5992500)
$LOG,4.270,AFSP,2,TERTIARY CODE SYNC (530,1,1.000)
```

## 3. 同期位置の妥当性

ログの括弧内の最初の値は、同期した時点での tertiary チップ番号です。
1 チップは 8 ms なので、ここからフレーム先頭からの経過時間を計算できます。

| PRN | 同期時刻 [s] | チップ番号 | × 8 ms [s] |
|-----|--------------|------------|------------|
| 2   | 4.270        | 530        | 4.240      |
| 3   | 4.380        | 543        | 4.344      |
| 8   | 4.926        | 613        | 4.904      |

どの PRN でも、チップ番号から求めた時間は受信時刻と約 30 ms 以内で一致して
います。シミュレータはフレーム先頭から信号を生成しているので
（`afs_sim.c`: `ichip = fsec*1000/8`）、この差は伝搬遅延などの違いと考えられ、
位相は正しく決まっていると判断できます。

## 4. 補足

2 秒での判定は、早く同期することと誤同期の危険とのバランスを取った設計です。
C/N0 が低い場合は相関ピークが 0.8 に届かず同期が遅れることがありますが、
1 秒（`N_TCHK`）ごとにシンボルを積み増して再探索するので、時間とともに
判定の確度は上がっていきます。

| マクロ        | 値   | 説明                                       |
|---------------|------|--------------------------------------------|
| `T_NPULLIN`   | 1.5  | 航法データ・secondary code 同期の開始時間 [s] |
| `N_TSYNC`     | 250  | 同期判定に必要な最小シンボル数（2 s）      |
| `N_TCHK`      | 125  | 同期探索・同期外れ判定の間隔（1 s）        |
| `THRES_TSYNC` | 0.8  | 同期判定の閾値（正規化相関）               |
